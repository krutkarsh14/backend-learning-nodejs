Express JS me Authentication (Beginner Guide in Hinglish)

==========================================
Basic Definitions
==========================================
- Authentication: Iska matlab hai "Pehchan karna". Jaise club me entry ke liye ID card check hota hai. Tum kaun ho ye prove karna.
- Authorization: Iska matlab hai "Ijazat dena". Jaise ID check hone ke baad aapko VIP lounge me jaane ki ijazat hai ya nahi.

==========================================
Authentication Flow in Express JS (Sequence)
==========================================

1. Setup:
   - Sabse pehle express server banate hain.
   - Hamein 2 important packages chahiye:
     a) bcrypt: Password ko encrypt karne (chupane) ke liye. Taki agar database hack ho jaye toh bhi passwords safe rahein.
     b) jsonwebtoken (JWT): Ek digital 'ticket' ya 'token' banane ke liye jo login ke baad user ko milti hai.

2. Registration (Sign Up):
   - Jab naya user aata hai, wo apna username aur password deta hai.
   - Hum password ko as-it-is save NAHI karte (Kyunki ye unsafe hai). 
   - Hum `bcrypt.hash()` ka use karke usko "Hash" (ek ajeeb si chupi hui string) me badal dete hain.
   - Fir ye username aur 'hashed password' database (ya array) me save karte hain.

3. Login (Sign In):
   - User wapas aake apna username aur password deta hai (taaki wo login kar sake).
   - Hum database me dekhte hain ki kya is username ka user hai? Agar hai, toh aage badho.
   - Hum `bcrypt.compare()` se check karte hain ki jo naya password abhi diya gaya hai, kya wo database wale hashed password se match karta hai?
   - Agar haan (Match = Success), toh hum JWT (`jwt.sign()`) generate karte hain (Ek 'secret key' ka use karke jo sirf server janta hai).
   - Ye Token hum user ko frontend pe bhej dete hain. Ab ye token user ka "Entry Pass / Ticket" ban gaya.

4. Middleware (The Security Guard):
   - Kuch API routes aisi hoti hain (jaise profile page, dashboard) jo sirf logged-in users ko milni chahiye. Isko "Protected Route" kehte hain.
   - Iske liye hum ek 'Middleware' (ek guard function) banate hain.
   - Middleware ka kaam hai: "Ticket check karna" har uss request pe jo private/protected hai.
   - Jab user frontend se API request bhejta hai, toh wo request headers me (Authorization: Bearer <token>) token lagakar bhejta hai.
   - Hamara Guard (middleware) `jwt.verify()` function ka use karta hai ye check karne ke liye ki kya ye token hamari "secret key" se hi bana hai? Kahin expired toh nahi?
   - Agar token sahi hai, toh `next()` call hota hai, yani request ko main function (route) tak aane diya jata hai.
   - Agar token galat ya missing hai, toh guard usko waheen rok ke "Access Denied" bhej deta hai.

==========================================
Short Summary
==========================================
1. Register: User deta hai password -> hum use hash karke database me save karte hain.
2. Login: User deta hai password -> hash karke check karte hain match hua ya nahi -> agar haan, to ek JWT Token bhej do.
3. Access Protected Route: User Token bhejta hai -> Middleware Token check/verify karta hai -> Verify ho jaye to Access allow kar do.
